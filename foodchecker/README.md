# FoodChecker

## Лабораторная работа 1

**Проектирование и реализация пользовательского интерфейса средствами фреймворка Jetpack Compose и Material Design 3**

**Цель работы:** освоить декларативный подход к построению пользовательских интерфейсов на платформе Android с использованием фреймворка Jetpack Compose. Изучить базовые функции, механизмы компоновки, управления состоянием и навигации. Овладеть инструментами дизайн-системы Material Design 3 для создания современных, адаптивных и стилизованных интерфейсов. Научиться применять темизацию, адаптивную верстку и анимации.

**Задание:** реализовать часть проекта, помеченную зеленым цветом, в соответствии со своим вариантом.

## Вариант: мобильное приложение для проверки состава продуктов со сканером штрихкодов

### Функциональная часть приложения

Приложение должно обеспечивать выполнение следующих ключевых функций:

1. Каталогизация и просмотр (Главный экран):
   - отображение истории проверенных товаров;
   - персональный профиль пользователя с указанием критических пищевых аллергенов;
   - быстрый поиск по истории.
2. Просмотр детальной информации:
   - полный разбор состава продукта: выделение опасных компонентов цветом, расшифровка Е-добавок, вывод вердикта («Безопасно» или «Противопоказано»).
3. Автоматизированное добавление:
   - сканирование штрихкода на упаковке товара с помощью камеры устройства.
4. Управление данными:
   - асинхронный сетевой REST-запрос к базе данных Open Food Facts (https://world.openfoodfacts.org/data) или аналогам;
   - реализовать логику дублирования (Fallback): если штрихкод отсутствует в сети, приложение предлагает переключить камеру в текстовый режим для прямого сканирования блока «Состав» с упаковки и сопоставления слов с медицинским реестром.

### Архитектурные особенности приложения

В качестве централизованного механизма внедрения зависимостей для всех архитектурных слоев приложения должен быть использован фреймворк Koin.

### Хранение данных

1. Основная база данных (реляционная):
   - хранит профиль аллергий пользователя, журнал проверенных продуктов и т.д.;
   - взаимодействие с БД осуществляется с помощью библиотеки Room.
2. Вспомогательное хранилище (нереляционная БД, Realm):
   - содержит медицинский реестр вредных химических добавок и аллергенов (уникальный id, общепринятый маркер, описание воздействия, степень риска).
